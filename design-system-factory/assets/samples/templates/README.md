# templates/ — 内容区模板样例（广发中后台系统）

**这些是「广发中后台系统」的真实模板，只作参考，不要照抄。**

引擎不带成品模板（见 `assets/engine/scripts/templates/README.md`）。
这个目录留着它们，是为了两件事：

1. **回答「一类模板大概需要哪些部分」** —— 不知道从哪下手时可以看一眼结构层次
2. **演示新结构下该怎么落位** —— 目录名 = `--type` 取值，与你要在包里建的结构一致

> **不要直接复制到你的包里。** 它们的结构、取值阶梯、间距档位都是广发的：
> 表格是不是「卡片式 + 固定操作列」、表单是垂直还是水平布局、间距阶梯有哪几档 ——
> 这些都是广发的设计决策，在你那套系统里没有验证过。
> 复制过去之后，你的规范里会凭空多出几十个「待填」的 Token 条目。

## 参考：广发是怎么分类的

以下分类法是**广发的**，放在这里只作参照 —— 你的系统该怎么分，按你的设计稿裁决。

### 表格（`list/`）

| 判断条件 | 广发选它 |
| :-- | :-- |
| 列数多、需横向滚动、操作列需常驻 | `fixed-action-table.html` |
| 列数少（≤6）、无横向滚动 | `basic-table.html` |

### 指标卡（`dashboard/`）

| 判断条件 | 类型 |
| :-- | :-- |
| 单个核心指标 + 迷你趋势图 | 基础指标卡 |
| 多个同级核心指标横向并排 | 同级指标卡 |
| 总量与分项占比关系 | 总分指标卡 |
| 多个独立指标 + 每卡 mini chart | 嵌套指标卡 |
| 多维指标通过页签切换 | 页签联动指标卡 |

### 浮层的结构约束（广发版）

以下 8 条是**广发给自己的浮层定的结构约束**，原本写在引擎的 `scripts/README.md` 里。
放在引擎里等于让每个新包都继承一套没验证过的结构决策，所以搬到了样例这边。

**你的系统该定哪些约束，从你的设计稿和评审里长出来**，不要照抄这 8 条。

| # | 广发的约束 | 广发为什么这么定 |
| :-- | :-- | :-- |
| 1 | Modal 必须三段式，`container` 强制 `padding: 0` | 否则分割线左右不到头 |
| 2 | Modal 头部 / 底部高度各自走 Token，勿写死数值 | 换肤与密度调整时不至于全库改 |
| 3 | Drawer 头部与 Modal **不同值**，勿混用 | 抽屉更窄，同一套内边距会显得空 |
| 4 | Drawer 禁用默认 `title` / `closable`，一律自定义 header，操作按钮放 header 右侧 | 抽屉的操作密度高，默认标题栏放不下 |
| 5 | 桌面端 Drawer **默认不生成 footer**，仅移动端或强流程才加 | 桌面端右侧抽屉纵向空间宝贵 |
| 6 | `body` 是唯一滚动区，禁止把操作区卷进滚动区 | 操作按钮滚出视口就找不到了 |
| 7 | 展示类浮层（详情、只读）不生成 footer；操作类（新增、编辑、审批）必须有固定可见操作区 | 只读场景多一行按钮是噪声 |
| 8 | 必须有视口兜底 `max-width: calc(100vw - 48px)`，且上下居中（禁止 `top: 100px`） | 窄屏上固定 `top` 会让浮层顶到屏幕外 |

> 本系统的约束要自己裁决：**能批量校验的写进 `foundation/conventions.json`**
> （`[E4]` 会逐条查），靠肉眼审是审不住的。

### 模板验收清单（广发版）

广发在 `scripts/README.md` 的「模板验收清单」里列的**系统自定项**：

- [ ] 分页器未出现 margin + padding 叠加造成的双倍间距
- [ ] 固定操作列使用 `border-collapse: separate`
- [ ] 多标签溢出用箭头、滚动条隐藏
- [ ] 指标卡 mini chart 为 SVG sparkline，非 img 占位
- [ ] 浮层容器 `padding: 0`，分割线横向到边缘
- [ ] 浮层上下居中且有 `max-width: calc(100vw - 48px)` 兜底
- [ ] Drawer 用自定义 header，未使用默认标题栏结构

> 这 7 条是**广发的验收点**。你的清单要从你的设计稿与历史评审里长出来——
> 照抄等于把别人的设计决策当成本系统的规范，而且你会检查一些你系统里根本不存在的结构。

## 怎么用

搭自己的模板时，起手用**骨架**，不是这些样例：

```bash
mkdir -p <包>/scripts/templates/list
cp <包>/scripts/templates/_skeleton.html <包>/scripts/templates/list/<名字>.html
```

样例的作用是**回答疑问**（「这类模板一般需要哪些部分」「`:root` 大概要登记什么」），
不是提供起点。起点是设计稿。

> 如果你确实想拿某份样例当起点改（而不是照抄），可以先把包建好，再用
> `init-package.js --seed-templates=<这个目录>` 带进去 —— 取值会被自动中性化成 `unset`，
> 逼你逐条回灌本系统的定稿取值。但**结构是否适用仍要人对着设计稿逐类确认**。
