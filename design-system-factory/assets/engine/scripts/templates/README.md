# templates/ — 本系统的内容区模板

**这个目录一开始是空的，这是对的。**

引擎不预置任何内容区模板。和 `layout/` 一样：一个系统里「列表页长什么样」的答案，
只能来自**本系统的设计稿或线上实测**，不能从别的系统搬。

> 这一点比布局更容易被放过，因为「表格就是表格、表单就是表单」听起来很合理。
> 但它只对了一半——**模板不只是结构，它还带着一整套取值阶梯**：
> 间距档（`--space-1..16`）、色板（`--chart-1..4`）、圆角档、阴影档。
> 把这些阶梯原样带过来，新系统的规范里就会凭空多出几十个「待填」条目，
> 而每一条看起来都像一个正经的规范项，没人知道它从哪来、对应什么组件。

---

## 目录里有什么

| 文件 | 是什么 | 会被 `new-page.js` 用吗 |
| :-- | :-- | :-- |
| `_skeleton.html` | 契约骨架，只声明「模板要满足什么」，不含任何页面结构 | 否（`_` 开头一律跳过） |
| `contract.json` | 结构性契约的声明（浮层遮罩类名 / 宽度档位 / 样式提取范围 / `--type` 取值清单） | **是**，生成器按它工作 |
| `README.md` | 本文件 | 否 |
| `<类别>/<名字>.html` | 本系统真正在用的内容区模板 | **是**，目录名即 `--type` 的取值 |

**目录名 = `--type` 取值。**

本包该有哪几类，是**本系统的答案**，这里刻意不列——列出来就等于把别的系统的类别集
当成了「中后台通用类别」。裁决依据是 `mine-tokens.js` 报告第 1 节「页面结构特征」
加本系统的设计稿。多标签栏那一类固定落在 `tabs/`（目录名由 `contract.json` 的
`tabsDir` 声明，可以改）。

一类可以有多个模板（同一类里的「基础版」与「紧凑版」都放一个目录）。
生成时只有一个就自动用它，有多个则要 `--template=<名字>` 指定。

## 怎么沉淀第一类模板

### 1. 先看本系统实际有哪几类页面

```bash
node <工厂>/scripts/mine-tokens.js --online=<采集JSON> --emit-tokens=tokens.draft.md
```

> `mine-tokens.js` 属于**工厂**，不在本包里——它是建包/沉淀阶段的工具，
> 不属于交付物。路径见建包时打印的「下一步」。

报告第 1 节列出采集到的结构信号（`hasTable` / `hasForm` / `hasModal`…）与据此推断的
页面类型——**推断是信号驱动的**：检出表格才推列表页，检出图表才推仪表盘页，
不是拿一张「中后台应该有哪几类」的清单往采集结果上套。

**只沉淀确实有的那几类**，否则等于凭空给系统加了一类页面，而它看起来像工厂要求的。

### 2. 起手用骨架

```bash
mkdir -p scripts/templates/<类别>
cp scripts/templates/_skeleton.html scripts/templates/<类别>/<名字>.html
```

命名用能一眼看懂结构的名字（`basic` / `with-fixed-action` / `compact` 都可以），
不要用 `tpl1` / `tpl2`。

搭的时候：

- **结构照设计稿。** 有哪些区块、什么顺序、怎么排布，全部按设计稿与线上实测来，
  不要凭「中后台的表格一般长这样」补。这是本目录存在的唯一理由。
- **取值先登记再回灌。** 用到的尺寸/色值先写进 `foundation/tokens.md`，
  再回灌本文件的 `:root`。反向操作必然产生双源漂移。
- **类名沿用本包前缀**（见包内 `SKILL.md`）。前缀是全库批量替换的锚点，
  另起一套会让后续替换漏掉这个文件。
- **标题用占位符。** 要填页面标题的地方写 `@@页面标题@@`，系统名写 `@@系统名@@`，
  生成时会按 `--name` / `--system` 填进去（见下方「与生成器的契约」）。
- **标「业务替换点」。** 凡是使用者需要改的地方（标题、字段、数据源、提交逻辑），
  都加 `<!-- 业务替换点：xxx -->`。缺了它，使用者不知道从哪下手。
- **演示区要标出来。** 为了让人看得见而造的触发按钮 / 假数据 / 说明文字，
  必须用 `@transient` 标记圈起来并加 `data-collect-ignore`——见下方「演示区」。
  不标的话，它会被注入别人的页面、被采集器当成你的设计取值。

### 3. 校验

```bash
node <包>/scripts/check-tokens.js <包> --strict
```

退出码 0 才算这类模板落地了。若本系统对某类模板有结构级约定
（例如「表格的金额列必须右对齐」「弹窗容器 padding 必须为 0」），
写进 `foundation/conventions.json`，由 `[E4]` 自动把关——
这类约定靠肉眼审是审不住的。

## 与生成器的契约

| 契约 | 内容 |
| :-- | :-- |
| **文件形态** | 一份**完整的 HTML 文档**（含 `<style>` 与 `<body>`）。生成器从中提取 style / body 内层 / script 三部分 |
| **落位** | `scripts/templates/<类别>/<名字>.html`，目录名即 `--type` 取值 |
| **`:root`** | 只写本模板用到的 Token；生成器会把内容区与多标签栏的 `:root` 合并进产物 |
| **文案占位** | 要填页面标题的地方写 `@@页面标题@@`（← `--name`），系统名写 `@@系统名@@`（← `--system`）。**生成器不认识任何具体系统的类名**，只认这两个占位符 |
| **替换点** | 需人工改的位置都标 `业务替换点` |
| **演示区** | 只为演示而存在的块用 `@transient` 标记圈起来（见下节），并加 `data-collect-ignore` |
| **浮层** | 若模板是浮层类别，类名与档位须与 `contract.json` 一致 |

### 文案为什么要用占位符

生成器里**没有**任何「弹窗标题的类名叫什么」这类知识——那是每个系统自己的事。
写死一个类名，等于引擎只对那个系统有效；换一个系统，`--name` 就填不进去了。

所以模板里主动声明：

```html
<h2 class="你的标题类名">@@页面标题@@</h2>
```

生成时 `@@页面标题@@` 被 `--name` 替换。没写占位符的模板不会被替换——
这不是 bug，是「模板没声明它要接哪个值」。

**HTML 注释里的占位符不替换。** 想在注释里写用法说明（`<!-- 也可写 @@页面标题@@ -->`）可以放心写，
生成后原样保留——否则会变成「也可写 产品列表」，读起来像生成器出了错。
反过来说：占位符写进注释就**不生效**，要真填值必须写在注释外的标签里。

## 演示区：两种标记，两个目的

模板里常有「为了让人看得见」而造的东西：触发按钮、假数据、版本说明、
「当前激活标签：首页」这类读数。它们**不是本系统的组件**，但很容易一路漏到下游。

漏出去会怎样，两条路都是真出过问题的：

| 漏到哪 | 后果 |
| :-- | :-- |
| **注入宿主页**（`--overlay` / `--tabs`） | 别人的页面里凭空多出「当前激活标签：首页」和一段版本说明 |
| **被采集器采到** | 演示区常用 `em` 相对单位，computed 出来是 `7px` / `11.9px` / `3.5px` 这类值，混进间距与圆角候选，还会压低「网格覆盖率」 |

所以要打**两个**标记，各管一件事：

### 1. `@transient` —— 注入宿主页时剔除

用注释把演示区圈起来，HTML 与 CSS 各包一份：

```html
<!-- @transient-start 演示用触发区（业务接入时删除） -->
<div class="demo-launch" data-collect-ignore>
  <button class="你的按钮类名" data-modal-open="modalForm">打开弹窗</button>
</div>
<!-- @transient-end -->
```

```css
/* @transient-start 演示区样式 */
.demo-launch { max-width: 800px; margin: 0 auto; }
/* @transient-end */
```

生成器只按标记切段，**不做任何 HTML 解析**（不数标签、不配对），
所以标记必须自己写对。开闭标记后面可以跟说明文字，写成
`<!-- @transient-start 演示区 -->` 也认。

**只在注入宿主页时剔除**——独立全屏页（浮层类别、`contract.json` 的 `standalone`
声明的类别、`--layout=none`）不剔除，因为那里演示区往往是页面上唯一能点的东西，
删了就成空白页。

### 2. `data-collect-ignore` —— 采集时跳过

给演示区的根元素加上，采集器会跳过**它和它的全部后代**。
这份属性跟着产物走，所以对「独立全屏页」也有效——那正是最容易被拿去采集的东西。

属性名可以改，采集时传 `__DSF_COLLECT__({ ignoreAttr: 'data-xxx' })`。

### 两个都要打，别只打一个

- 只打 `@transient`：注入宿主页干净了，但独立页被采集时照样污染
- 只打 `data-collect-ignore`：采集干净了，但宿主页里会多出一整块演示 DOM

引擎自带的「演示入口条」（`--overlay` 注入的那个）已按此约定打好标记，
不用你管；你自己的演示区要自己打。

## contract.json 声明了什么

浮层比普通页面多一层耦合：生成器要把它们**注入宿主页面**，
需要知道遮罩用哪个类名、有哪几档宽度、注入时该从模板里带走哪些样式规则。
这些**每个系统都不一样**，所以不写在生成器里，而是声明在 `contract.json`：

| 字段 | 作用 |
| :-- | :-- |
| `types` | `--type` 取值清单。**可选**：留空 = 不设白名单，完全按 `templates/` 下的目录名发现 |
| `overlay.<类别>.label` | 生成器输出里的中文称呼，如「打开弹窗（表单 640）」 |
| `overlay.<类别>.mask` | 遮罩类名。生成器靠它定位结构块，并给它加作用域前缀 |
| `overlay.<类别>.openAttr` | 触发属性，如 `data-<类别>-open` |
| `overlay.<类别>.needles` | CSS 选择器片段（不带前导点），命中即提取该规则 |
| `overlay.<类别>.defaultSize` / `sizes` | 宽度档位：键名出现在 `--overlay=<类别>:<档位>` 里，`label` 是显示名，`cls` 是模板里的类名 |
| `alias` | 组合别名，如 `both` 展开成哪几类 |
| `standalone` | 不套布局、直接产出独立全屏页的类别 |
| `tabsDir` | 多标签栏模板所在目录 |

这和 `foundation/conventions.json` 是同一个思路：校验器只提供通用断言类型，
结构约定由本系统声明。凡是「只对某一个系统成立」的知识，都不该写死在工具里。

## 怎么裁决本系统的契约

**引擎建包时 `contract.json` 是空契约**（`types: []`、`overlay: {}`）。
这不是漏填——一份填满的契约是「某一个系统的设计决策」，
把它预置进引擎，等于让每个新包都继承一套没验证过的答案。

裁决要回答两类问题：

### A. 本系统有哪几类页面 → `types`

| 从哪来 | 怎么读 |
| :-- | :-- |
| `mine-tokens.js` 报告第 1 节「页面结构特征」 | 采集到的结构信号与据此推断的页面类型 |
| 本系统的设计稿 | 报告只认它认识的信号；设计稿里有而采集没覆盖的类别，以设计稿为准 |

`types` **可以留空**——那时生成器完全按 `templates/` 下的目录名发现，
建了什么目录就有什么类别。想提前锁定清单（例如先定下要建哪几类、模板稍后再补）
才需要填它。

### B. 浮层分几类、每类几档、遮罩叫什么 → `overlay`

| 字段 | 从哪裁决 |
| :-- | :-- |
| 有哪几类浮层 | 报告第 1 节的 `hasModal` / `hasDrawer` 信号 + 设计稿里实际画的浮层 |
| `mask` / `openAttr` | **本系统的类名与属性名**。看本系统已有实现的 DOM，或按本包前缀新起一套 |
| `sizes`（档位与宽度） | 从设计稿量：这套系统实际画了几档宽度、每档多宽。**档位数不是通用常量** |
| `needles` | 反推：浮层注入宿主页时，需要从模板里带走哪些样式规则才不残缺（浮层本体、按钮、表单控件、表格、链接…） |
| `defaultSize` | 不写档位时用哪一档，通常是使用频率最高的那个 |
| `standalone` | 哪些类别不套布局（登录页、错误页这类独立全屏页） |

裁决完写进 `contract.json`，再建 `templates/<类别>/` 放模板，**两边的类名与档位要对齐**。

> 一份填满的样子：工厂包 `assets/samples/contract.sample.json`。
> 那是广发的答案——**只作参照，不要照抄**。照抄过来，
> 你的浮层模板会带着一套没在设计稿上验证过的宽度档上线。

契约还没裁决时，`--overlay` 与 `--type` 会**拒绝执行并打印该走哪一步**，
不会静默用一个默认值糊过去。

## 一类模板都不做行不行

行——如果本系统还没有需要沉淀的页面类型。但要清楚代价：

- `new-page.js --type=<类别>` 在该目录为空时会**报错并打印沉淀步骤**，
  不会静默产出空页面或退化到别的结构
- `check-tokens.js` 与布局沉淀不受影响，规范仍然可用

**生成器的价值建立在「模板已按本系统沉淀」之上。** 没有模板时它帮不上忙，
这比它偷偷用别人的结构要好。
