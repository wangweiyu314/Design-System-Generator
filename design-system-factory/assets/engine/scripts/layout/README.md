# layout/ — 本系统的页面外壳

**这个目录一开始是空的，这是对的。**

引擎不预置任何布局。布局是「本系统的页面外壳长什么样」的答案，
这个答案只能来自**本系统的设计稿或线上实测**，不能从别的系统搬。

> 从别的系统抄一套布局过来，等于用一个没在本系统验证过的结构冒充答案。
> 更糟的是它看起来是能跑的——直到有人发现侧栏宽度、面包屑位置、
> 多标签行为全都不对，而那时它已经被复制进几十个页面了。

---

## 目录里有什么

| 文件 | 是什么 | 会被 `new-page.js` 用吗 |
| :-- | :-- | :-- |
| `_skeleton.html` | 契约骨架，只声明「布局模板要满足什么」，不含任何外壳 | 否（`_` 开头一律跳过） |
| `README.md` | 本文件 | 否 |
| `<名字>.html` | 本系统真正在用的布局，一个外壳一份 | **是**，文件名即 `--layout` 的取值 |

---

## 怎么沉淀第一套布局

### 1. 先看本系统实际有几种外壳

跑挖掘脚本，看报告第 2 节「布局候选」：

```bash
node <工厂>/scripts/mine-tokens.js --online=<采集JSON> --emit-tokens=tokens.draft.md
```

> `mine-tokens.js` 属于**工厂**，不在本包里——它是建包/沉淀阶段的工具，
> 不属于交付物。路径见建包时打印的「下一步」。

那一节按**几何指纹**（侧栏在哪一侧、多宽，顶栏多高、是否通栏，有没有面包屑/多标签）
把线上页面聚成若干组，每组就是一套外壳。单页样本会被明确标注「样本不足」——
一个页面的指纹不构成结论。

### 2. 逐套搭出来

```bash
cp scripts/layout/_skeleton.html scripts/layout/<名字>.html
```

命名用能一眼看懂外壳特征的名字（比如「侧栏 + 顶栏」「仅顶栏」这种结构描述），
不要用 `layout1` / `layout2`。名字会成为 `--layout=<名字>` 的取值，所以它得能自解释。

搭的时候：

- **结构照设计稿**。侧栏在哪一侧、多宽，顶栏是否通栏、多高，面包屑有没有独立行——
  都按采集到的指纹与设计稿来，不要凭「中后台一般长这样」补。
- **三个插入点标记必须保留**（这是与生成器的唯一契约）：

  | 标记 | 必填 | 作用 |
  | :-- | :-- | :-- |
  | `<!-- @content-slot -->` | ✅ | 业务内容插入点。缺了 `new-page.js` 直接报错 |
  | `<!-- @tabs-slot -->` | 选填 | 多标签栏插入点（`--tabs` 用）。没有就是「这套外壳不含多标签栏」 |
  | `<!-- @page-title -->` | 选填 | 页面标题文本插入点（`--name` 用） |

  > **标记后面写什么，生成后就会原样留下什么。** `new-page.js` 只替换标记本身
  > （`<!-- @page-title -->` → `--name`），不清理它后面的文字。
  > 所以留一个空标题位：`<h1 class="你的类名"><!-- @page-title --></h1>`。
  > 写成 `<!-- @page-title -->页面标题` 会得到「产品列表页面标题」。
  > 没留该标记时，`--name` 只落到 `<title>`。

  > **★ 标记的「示范性引用」只能写在 `<style>` / `<script>` 里，不能写在正文注释里。**
  > 换标记时只认「`<style>`/`<script>` 之外」的第一个出现。
  > `_skeleton.html` 的头部注释就示范了这三个标记的写法（它在 `<style>` 的 CSS 注释里），
  > 照抄骨架搭出来的布局天然带一份这样的引用——引擎必须能跳过它。
  > 把示范写进正文的后果是：**内容被注进注释里、真插入点原封不动留着**，
  > 而 `[E1]`–`[E5]` / `[W1]` / `[I1]` **全部是绿的**——它们只看颜色与 Token。
  > 这类错误只能靠把产物渲染出来量几何才会暴露，见 `references/04-pitfalls.md`。
  > 搭完布局后自查：正文里搜 `@content-slot`，应该一处都搜不到（生成后）。

- **类名沿用本包前缀**（见包内 `SKILL.md`）。前缀是全库批量替换的锚点，
  另起一套会让后续替换漏掉这个文件。
- **取值先登记再回灌**：用到的尺寸/色值先写进 `foundation/tokens.md`，
  再回灌本文件的 `:root`。反向操作必然产生双源漂移。

### 3. 校验

```bash
node <包>/scripts/check-tokens.js <包> --strict
```

退出码 0 才算这套布局落地了。若本系统对布局有结构级约定
（例如「面包屑必须是内容区的首子元素」「侧栏背景必须是某 Token」），
写进 `foundation/conventions.json`，由 `[E4]` 自动把关——
这类约定靠肉眼审是审不住的，见 `assets/samples/conventions.sample.json`。

## 一个布局都不做行不行

行。已有项目里加页面时用 `--layout=none`，只产出内容区，外壳由宿主管。

```bash
node <包>/scripts/new-page.js --type=<类别> --name=<页面名> --layout=none
```

只有「0→1 新建系统」才必须沉淀布局——那种场景下没有宿主可以借。
